# Diagnostic Report: Stacking Ensemble Performance Analysis

**Project:** Telecom Customer Churn Prediction & Retention Decision Support System  
**Dataset:** `data/balanced_telco_churn.csv` ($N=8,000$, 50% Churn / 50% Non-Churn)  
**Partition:** `data/train_original.csv` ($N=6,400$), `data/test_original.csv` ($N=1,600$)  
**Date:** October 2026  

---

## Executive Summary

The project evaluates four models: Random Forest (RF), XGBoost, LightGBM, and a Stacking Ensemble. Prior to optimization, the baseline Stacking Ensemble exhibited lower ROC-AUC (0.9894 vs XGBoost 0.9901), worse Log-Loss (0.1379 vs XGBoost 0.1232, LightGBM 0.1255), worse Brier Score (0.0362 vs XGBoost 0.0347), and lower default Accuracy than Random Forest (95.44% vs 95.50%).

Through systematic code inspection, mathematical analysis, and out-of-fold (OOF) validation experiments, we identified the exact structural and statistical causes of this underperformance.

---

## Systematic Investigation of Diagnostic Questions

### 1. Are base-model predictions supplied to the meta-learner generated out-of-fold?
**Finding:** Yes.  
**Evidence:** In `scripts/train_churn_v2.py` (lines 248–266), a 5-fold `StratifiedKFold` split was used to populate `oof_rf`, `oof_xgb`, and `oof_lgbm`. The meta-features passed to `LogisticRegression` during training consisted strictly of these out-of-fold predictions.

### 2. Is the meta-learner trained on predictions from samples that base models already fitted?
**Finding:** No in-sample leakage during meta-training, but architectural defect in object state.  
**Evidence:** The meta-features were out-of-fold. However, in `evaluate_model_cv`, the same model instance (e.g., `xgb_model`) was passed via a lambda closure and re-fitted fold-by-fold without explicit `sklearn.base.clone()`. Furthermore, the full base models were refitted on the full 6,400 training samples *after* CV, which is standard stacking practice, but the meta-learner was fitted on the OOF probabilities generated by the fold models.

### 3. Does preprocessing or resampling occur before cross-validation, causing leakage?
**Finding:** Minor scaling leakage before CV; no data leakage between train and test.  
**Evidence:** In `scripts/train_churn_v2.py` (lines 195–200), `StandardScaler` was fitted on the entire `X_train_raw` (6,400 rows) before running the 5-fold CV. While tree models are invariant to monotonic scaling, any linear meta-learner or linear base model is exposed to out-of-fold distribution information. In the test partition, scaling was strictly transformed using the training scaler, so test data remained untouched.

### 4. Do training and inference use identical column ordering and transformations?
**Finding:** Yes.  
**Evidence:** Feature transformations are centralized in `scripts/feature_engineering_v2.py` and wrapped in `ChurnV2StackingEnsemble`. Both train and inference pipelines use identical 27 feature columns and 7 continuous scale columns in the exact same sequence.

### 5. Are the base models too highly correlated to provide complementary information?
**Finding:** **PRIMARY CAUSE.** Extreme multicollinearity between base models.  
**Evidence:** Pearson correlation matrix between predicted test probabilities:
- $r(\text{RF}, \text{XGB}) = 0.9918$
- $r(\text{RF}, \text{LGBM}) = 0.9905$
- $r(\text{XGB}, \text{LGBM}) = \mathbf{0.9984}$ (Spearman $\rho = 0.9920$)

Because XGBoost and LightGBM use nearly identical gradient boosting objectives, tree depths, and feature subsets on the 27 engineered features, their predictions are essentially collinear. Stacking benefits from *diversity* (e.g., combining linear models, neural networks, and tree models with uncorrelated error patterns). Here, the base models provide near-redundant signals.

### 6. Is the meta-learner underfitting or overfitting?
**Finding:** Overfitting to collinear features combined with probability distortion.  
**Evidence:** The meta-learner in `train_churn_v2.py` is an unweighted, un-tuned `LogisticRegression(C=1.0)` taking raw probabilities $p \in [0, 1]$. Because the three input features have pairwise correlations $> 0.99$, the design matrix $X_{\text{meta}}^T X_{\text{meta}}$ is ill-conditioned. The resulting learned coefficients are $[2.586, 3.122, 1.944]$ with intercept $-3.808$. This unstable weighting magnifies small differences between collinear predictors, degrading probability calibration.

### 7. Does training data contain enough examples from both classes?
**Finding:** Yes. Perfect 50/50 class balance.  
**Evidence:** The training set contains exactly 3,200 churners and 3,200 non-churners. The test set contains exactly 800 churners and 800 non-churners. There is no class deficiency or rare-class pathology.

### 8. Does the ensemble combine probabilities consistently?
**Finding:** **PRIMARY CAUSE.** Flawed meta-learner input space (Raw probabilities vs. Logits).  
**Evidence:** Feeding raw probabilities bounded in $[0, 1]$ into a standard logistic regression applies a sigmoid on top of an already sigmoid-like probability:
$$P(\text{churn}) = \sigma(w_1 p_{\text{RF}} + w_2 p_{\text{XGB}} + w_3 p_{\text{LGBM}} + b)$$
This double-sigmoid compression distorts the extremes (probabilities near 0.0 and 1.0 are squashed toward 0.05 and 0.95), directly damaging Log-Loss (0.1379 for Stacking vs 0.1232 for XGBoost) and Brier Score (0.0362 vs 0.0347). Transforming base probabilities to log-odds (logits) or using convex soft voting avoids this compression.

### 9. Is a threshold of 0.50 unsuitable for the project's recall-focused objective?
**Finding:** Yes, for business cost minimization, but threshold tuning in baseline had trade-offs.  
**Evidence:** In the baseline, a threshold sweep lowered $\tau$ to 0.26, boosting test Recall from 95.25% to 96.25% (+8 true positives), but increasing False Positives from 35 to 43 (+8 false alarms), reducing Precision from 95.61% to 94.71%. For churn retention where false negatives carry higher business cost ($C_{FN} > C_{FP}$), $\tau \approx 0.30 - 0.40$ is economically optimal, but this must be chosen via formal business cost functions on OOF data.

### 10. Are model calibration, class imbalance handling, or inconsistent hyperparameters degrading results?
**Finding:** Yes.  
**Evidence:**
- Base models were tuned individually with generic grid parameters without joint ensemble optimization.
- The 50/50 balanced dataset reflects an artificially balanced environment (real-world churn is typically 15–25%). In this 50/50 domain, probabilities reflect balanced-prevalence posteriors.
- Lack of calibration inside the stacking pipeline caused the meta-learner to produce worse probability metrics than the individual boosted trees.

### 11. Is the stacking ensemble evaluated on exactly the same records as the individual models?
**Finding:** Yes.  
**Evidence:** Verified in `scripts/ensemble_optimization_baseline.py`. All four models are evaluated on the exact same 1,600 rows in `data/test_original.csv` using identical metric implementations and ground-truth labels.

### 12. Does the current ensemble actually outperform simple probability averaging or hard voting?
**Finding:** **NO.** Simple soft voting outperforms the baseline Stacking Ensemble.  
**Evidence:**
- Baseline Stacking Ensemble ($C=1.0$): Test Acc = 95.44%, ROC-AUC = 0.9894, Log-Loss = 0.1379, Brier = 0.0362.
- Equal Soft Voting ($1/3, 1/3, 1/3$): Test Acc = 95.44%, ROC-AUC = 0.9894, Log-Loss = **0.1263**, Brier = **0.0347**.
- Optimized Soft Voting (Weights: RF 0.00, XGB 0.62, LGBM 0.38): Test Acc = 95.44%, ROC-AUC = **0.9899**, Log-Loss = **0.1238**, Brier = **0.0348**.
- Logit-Transformed Stacking ($C=0.1$): Test Acc = **95.56%**, ROC-AUC = **0.9896**, Log-Loss = **0.1242**, Brier = **0.0346**.

## Error Analysis & Bayes Noise Floor

An analysis of test-set error patterns ($N=1,600$) reveals:
- Total Errors: RF = 72, XGB = 77, LGBM = 74, Baseline Stacking = 73.
- **Shared Errors Across All 3 Base Models:** 63 errors out of 72–77 (82.9% to 87.5% shared error rate).
- In `scripts/generate_balanced_dataset.py`, an intentional label noise rate of `noise_rate = 0.05` (5%) was injected into the synthetic data generation process.
- This creates an irreducible Bayes error rate of approximately 5.0%, imposing a theoretical performance ceiling of ~95.0% accuracy on this dataset.
- Because base models are tree-based and share 27 identical features, they misclassify the exact same noisy edge cases.

## Actionable Optimization Strategy

To resolve the measured defects without violating project safety or compatibility:
1. **Logit Transformation & Regularized Stacking:** Convert base probabilities to log-odds ($\text{logit}(p) = \log\frac{p}{1-p}$) before feeding them into the meta-learner, and tune regularization parameter $C \in [0.01, 0.1, 1.0]$.
2. **Convex Soft Voting (Non-Negative Least Squares):** Provide an optimized weighted soft voting ensemble with non-negative weights summing to 1, optimized purely on OOF cross-validation.
3. **Repeated Stratified CV:** Validate across 5-fold $\times$ 2-repeat CV to confirm fold-level statistical significance.
4. **Calibrated Probabilities:** Apply Isotonic / Sigmoid probability calibration on meta-predictions.
5. **Cost-Based Threshold Optimization:** Document operating thresholds across $\tau \in [0.10, 0.90]$ under explicit retention business cost matrices.
